01 / LESS GLUE

每个服务，少写一套通知。

业务只描述发生了什么。渠道密钥、投递路由与失败重试，集中在网关管理。

02 / MORE EVIDENCE

入队之后，仍有迹可循。

区分已接收、等待投递与实际送达。查看尝试次数和死信，追踪故障发生与恢复。

03 / YOUR CONTROL

数据留在自己的服务里。

单实例自托管，服务端渲染后台。Agent 只读取指定路由的告警，不修改故障。

01 / LOCAL EXPERIENCE

运行真实的本地后台

需要 Docker Compose、OpenSSL 和 curl。临时凭据由脚本生成；在空后台配置渠道、路由和客户端。

git clone https://github.com/xiongwei-git/alertbridge.git
cd alertbridge
./scripts/local-demo.sh up

打开 http://127.0.0.1:18081/admin/
本地 HTTP 环境仅供测试，不要暴露到公网。

02 / YOUR INFRASTRUCTURE

部署你的通知中枢

使用官方 GHCR 镜像与 Docker Compose。应用绑定 loopback，由 Nginx 提供 HTTPS。数据库与主密钥卷成对备份。

不确认或关闭故障，不执行系统命令，不自动唤醒 Agent。账号可用性与连接界面以实际环境为准。

SMALL BY DESIGN

边界清楚，才能放心使用。

适合这样的需求

个人基础设施、小团队、单节点运维。希望统一脚本通知，有持久队列、清晰投递记录，并允许 Agent 按需读取。

需要其他方案的场景

监控采集、多实例高可用、值班排班、告警聚合、超时升级、告警确认和自动修复，当前不在项目能力范围内。

把它变成你愿意长期使用的工具。

从一个最小接入案例、一份更清楚的文档，或一个可复现的问题开始。

# ADR-012: 官网、公共演示与运行服务隔离

## 状态

Accepted，2026-10-17。

## 背景

开源访问者需要在不持有凭据、不接触维护者生产告警的情况下理解路由、故障生命周期与 Agent 只读查询。GitHub Pages 只能托管静态内容，不能运行 Go/SQLite 服务。

## 决定

- `site/` 提供无依赖静态官网与浏览器内模拟 Demo，同一产物可部署 GitHub Pages 或独立宝塔静态站。
- Demo 显示虚构事件、模拟投递结果与明确的模拟标识；不请求生产 API、不保存输入、不收集凭据、不开放匿名后台。
- 真实功能验收仍由隔离 Docker E2E 和用户自己的本地 Demo 完成。
- Pages 工作流只手动触发，发布前必须通过网站检查。不在 `main` 推送时自动覆盖网站，且不调用镜像发布或生产部署。
- v1.0 作为开源体验里程碑候选；此轮保持 `VERSION` 在已存在的 v0.4.2，不让尚未发布的 v1.0 出现在可执行安装命令里。正式 tag、镜像发布和生产升级各自明确执行。

## 备选方案与后果

公共可写 Go 后台需要隔离凭据、滥用控制和定期清理，维护成本更高，故不采用。静态模拟不能证明真实认证、持久化、重试或通知送达，页面和文档需持续保留此边界。宝塔域名和 HTTPS 验收独立于通知服务，不改现有反向代理、容器、数据库或主密钥。

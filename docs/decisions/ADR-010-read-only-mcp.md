# ADR-010: 同进程只读 MCP 查询

## Status

Accepted — 2026-10-17

## Context

Agent 需要查看历史告警、投递结果和当前故障。现有入站凭据只授权发送，不能因此获得读取其他来源数据的权限。服务应继续保持单进程、单 SQLite 连接与单投递 Worker。

## Decision

- 用官方 Go MCP SDK 提供无状态 Streamable HTTP `/mcp`，使用 JSON 响应，不保留常驻会话。
- 三个工具：`list_alerts`、`get_alert`、`list_active_incidents`；不提供确认、恢复、管理配置或执行命令工具。
- 独立高熵 Bearer 令牌，部署配置只保存 SHA-256 摘要，固定允许查询的路由。默认不注册入口，配置无效拒绝启动。
- 一个部署先支持一个查询身份；60 次/分钟的独立持久化限流，分页 1–100 条，正文 16 KiB，处理超时 5 秒。
- 复用原 SQLite 连接。事件按 `(created_at,id)` 游标查询；活跃故障用独立分页，实时查询不承诺快照、消息消费或超过保留期的补读。
- `list_alerts` 默认正序兼容增量读取，增加显式 `order=desc` 直接读取最近告警，避免 Agent 遍历历史。正倒序都按服务接收时间与 ID 稳定排序；游标绑定方向，旧游标视为正序。倒序不返回容易误用于增量同步的 `checkpoint`，增量消费者继续使用正序。工具 Schema 和说明明确最新告警的调用方式；不增加新工具、依赖或数据迁移。
- 告警内容明确标为不可信数据；不返回原始 payload、密钥、配置或投递错误原文。

## Alternatives Considered

- 独立 MCP 服务：增加进程、认证和数据库访问部署成本。
- 自写 JSON-RPC：协议和兼容维护成本高于官方 SDK 带来的有限依赖增长。
- 复用发送令牌：混淆读写权限边界。
- 一开始加入 OAuth、多身份 UI 和事件订阅：超过当前只读需求，后续按真实客户端兼容性扩展。

## Consequences

镜像会因 SDK 增大；本地 Docker E2E 参考镜像 21,486,201 字节，空闲内存 13.24 MiB，仍无需额外运行时依赖。静态凭据适合支持自定义请求头的客户端，不等价于所有云端客户端的 OAuth 兼容性。Dots 主动唤醒可以后续按官方 MCP Events 实现，本次不包含该能力。轮换或变更读取范围需要重建容器。

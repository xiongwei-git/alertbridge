# 开源体验审视与 v1.0 候选计划

检查日期：2026-10-17。基线：v0.4.2 源码；本次仅改开放协作、示例和独立网站，不修改运行服务。

| 维度 | 现状判断 | 本次改造 |
| --- | --- | --- |
| 定位 | 功能完整但首页偏运维手册，首次阅读路径长 | 清晰价值主张、适用/不适用场景、英文章节入口 |
| 试用 | 只有需要 Docker 的本地后台 | 静态浏览器 Demo + 原有真实 Docker Demo，两者分开标注 |
| 接入 | API/OAuth 有契约，缺少任务导向实例 | 标准库 Python HMAC 示例、Dots 提问与验收清单 |
| 信任 | Apache-2.0、ADR、安全容器与 CI 已有基础 | 安全政策、贡献流程、行为准则、Issue/PR 模板 |
| 发布 | GHCR 为权威，已有多架构/供应链证明 | 保留发布边界，官网 Pages 单独手动发布 |
| 展示 | README 截图依赖外链 | 可移植静态官网、响应式交互和独立部署说明 |
| 兼容性 | v1 API，SQLite 单实例 | v1.0 候选不改变 API/数据库/生产配置 |

## 核心价值

让业务脚本只关心“发生了什么”，由一个可自托管的小服务统一处理“谁能发、发给谁、是否重复、有没有送达”；Agent 在明确路由权限下读取这些事实。不要将其描述为监控采集平台、值班系统或自动修复 Agent。

## 发布门槛

1. Go 测试、vet、release 检查、隔离 Docker E2E 和静态网站检查通过。
2. 官网桌面/移动视图、模拟故障/恢复/重置流程验收。
3. 审阅 v1.0 候选变更记录和文档；维护者确定发布日期，再同步 VERSION、安装示例及 tag。
4. GitHub Pages 发布后验证真实公开 URL；宝塔在独立域名解析后验证 HTTPS 与 Demo。两者不要求升级现有服务。
5. Dots 账号端安装仍需有权限的真实账号验收，不将模拟或协议测试称为账号端完成。

## 后续按需求推进

英文文档逐步完善、可选的跨版本备份恢复演练、更多真实接入案例。高可用、第三方解析器、聚合/升级、MCP Events 主动唤醒仍需要独立需求和 ADR，不为开源外观而引入。
